# Участнику №2: подключение интерфейса JINALYS AI

Участник №2 — ответственный за итоговую интеграцию. Ветка интерфейса: `codex/app-demo`. Не заменяйте свой backend этой веткой и не копируйте все файлы поверх проекта без проверки.

## 1. Сохранить свою работу
В своём клоне репозитория:
```powershell
git status
git branch --show-current
```
Зафиксируйте свои изменения в своей ветке. Убедитесь, что `git status` показывает чистое рабочее дерево. Не добавляйте ключи, локальные модели, аудио с персональными данными и виртуальные окружения.

## 2. Получить интерфейс и создать интеграционную ветку
Оставаясь на своей готовой backend-ветке:
```powershell
git fetch origin
git switch -c integration/jinalys-full
git diff --stat HEAD...origin/codex/app-demo
git merge --no-commit --no-ff origin/codex/app-demo
```
Если имя интеграционной ветки занято, выберите новое свободное имя. Merge может завершиться конфликтами — это ожидаемо при независимой разработке.

### Как разрешать конфликты
- `README.md`: объединить документацию frontend и фактическую установку ваших AI-моделей.
- `package.json`: сохранить зависимости обеих частей; если разные приложения используют разные стеки, сохранить их раздельно и адаптировать пути frontend.
- `package-lock.json`: после согласования package.json выполнить `npm.cmd install`, не склеивать lock вручную.
- `.env.example` и `.gitignore`: объединить настройки; примеры без настоящих секретов.
- `app/api/meetings/route.ts`: наша версия — заглушка 503, ваша рабочая обработка должна заменить её через адаптер.
- `lib/contracts.ts`: формат frontend является границей API. Не переписывать все внутренние модели backend; преобразовать ответ на границе.
- Не использовать массово `--ours`/`--theirs` и не применять `git reset --hard`.

После решения конфликтов:
```powershell
git status
npm.cmd install
npm.cmd test
npm.cmd run build
git add .
git diff --cached --stat
git diff --cached --check
git commit -m "chore(integration): merge meeting UI with backend"
```
Если пока не получается объединить, `git merge --abort` возвращает состояние до merge (исходно дерево должно быть чистым).

## 3. Сначала запустить демо frontend
```powershell
npm.cmd ci
npm.cmd run dev
```
Открыть http://127.0.0.1:3000 → «Демоны ашу». Ожидаются 3 поручения и 3 участника; DOCX скачивается. Этот шаг не проверяет ваши модели.

## 4. Подключить реальный pipeline
Точка входа — `app/api/meetings/route.ts`. Сейчас она возвращает 503; это намеренная заглушка.

Запрос браузера: `POST /api/meetings`, `multipart/form-data`, поле `audio` (MP3/WAV).

Порядок обработки:
1. Сервер проверяет файл: размер до 400 МБ, содержимое/формат, ограничения длительности.
2. Локальный speech-модуль участника №1 возвращает транскрипт и speaker IDs.
3. Локальный protocol-модуль участника №2 формирует поручения и summary.
4. Адаптер преобразует результат в `MeetingProtocol` и валидирует через `protocolSchema` из `lib/contracts.ts`.
5. HTTP 200 возвращает объект `MeetingProtocol` напрямую, **без обёртки result/data**.

Если backend на Python/FastAPI или отдельном сервисе, Next route должен вызывать ваш локальный HTTP endpoint на сервере. Его адрес и port взять из вашего backend, а не придумывать. Переменные URL/модели добавить в `.env.example` и README. Локальные runtime доступны машине Next.js; `127.0.0.1` внутри контейнера означает сам контейнер.

Если API принимает `file`, а не `audio`, переименовать поле в серверном адаптере. Браузер продолжает работать с тем же `/api/meetings`; CORS тогда не нужен. Не указывать внешние cloud AI endpoints.

UI ожидает один финальный ответ и отменяет ожидание через 3600 секунд (60 минут). Если обработка дольше — согласовать job/polling или SSE; не возвращать ложный успешный ответ и не показывать фиктивный прогресс. Клиентская отмена сама по себе не останавливает модель на сервере.

Ошибка: HTTP 4xx/5xx с `{ "error": { "code": "...", "message": "..." } }`. Не отдавать ключи, промпты или полный traceback в браузер.

## 5. Минимальный пример успешного ответа
```json
{
  "title": "Тестовое совещание",
  "date": "2026-09-23",
  "transcript": [{"id":"s1","speakerId":"SPEAKER_00","speakerName":"Айгүл","start":0,"end":8,"text":"Асқар, есепті жұмаға дейін дайындаңыз.","language":"kk"}],
  "summary": "Асқарға есепті дайындау тапсырылды.",
  "topics": [{"title":"Есеп","summary":"Есепті дайындау мерзімі талқыланды."}],
  "actionItems": [{"id":"a1","task":"Есепті дайындау","assignee":"Асқар","deadlineText":"Жұмаға дейін","deadline":"2026-09-25","sourceSegmentIds":["s1"],"confidence":0.95,"needsReview":false}]
}
```
Пример синтетический. Реальные даты должны вычисляться по дате/часовому поясу совещания. UI ввода этих metadata пока нет: добавьте его совместно с расширением контракта либо оставляйте неразрешённые даты null. start/end — секунды; confidence — 0..1; неизвестные assignee/deadline/deadlineText — null. sourceSegmentIds должны указывать на существующие реплики. Speaker, произносящий поручение, и assignee, выполняющий его, могут быть разными людьми.

## 6. Проверить весь сценарий
- Запустить необходимые локальные модели, speech/backend и Next.js в порядке, описанном в обновлённом README.
- Загрузить смоделированную RU запись, затем KK и mixed запись.
- Проверить реальные слова, разделение спикеров и соответствие поручений записи.
- Убедиться: обсуждение идеи не становится поручением; неизвестные сроки и имена не выдуманы.
- Нажать «Дереккөзді көру»; должна открыться подтверждающая реплика.
- Проверить поиск/сүзгі, светлую/тёмную тему, DOCX и повторный запрос.
- Проверить отсутствие модели, неверный файл и ошибку backend: UI должен показать ошибку.
- Не использовать демо как доказательство реального распознавания речи.

## 7. Подготовить итоговый README
В текущей UI-ветке README честно описывает только frontend. После интеграции №2 добавляет:
- реальные названия/версии моделей, runtime, RAM/GPU/диск;
- команды загрузки моделей, установки и запуска каждого сервиса;
- все env из кода и `.env.example`, без секретов;
- фактическую архитектуру speech → diarization → extractor → verifier → summary;
- путь к безопасным тестовым аудио и ожидаемые результаты RU/KK/mixed;
- реализованные возможности отдельно от планов, известные ограничения;
- подтверждение, что аудио/текст не отправляются во внешние cloud AI API.

Затем выполнить инструкции README с чистой установки. Не обещать качество и функции, которые не проверены.
