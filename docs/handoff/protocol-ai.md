# Protocol AI — реализация и интеграция

Статус: реализованы локальный адаптер Ollama, extraction, нормализация сроков,
verifier, summary, Python API и CLI. Модульные тесты используют тестовый адаптер.
Реальный smoke test на Qwen3 4B пройден; интеграция с speech/UI пока не проверена.
Контракт предложен на основании командного плана; участники №1 и №3 ещё не подтвердили его.

## Вход и выход

Реальный Python-интерфейс: generate_meeting_protocol(transcript, metadata) -> dict.
Импорт: from protocol import generate_meeting_protocol.
Необязательный on_progress(stage) получает extracting, verifying, summarizing, done.
Ошибки ProtocolError означают, что полноценного протокола нет; скрытой подмены fixture нет.

Схемы: protocol/contracts/protocol.schema.json, JSON Schema Draft 2020-12.
Корень схемы проверяет MeetingProtocol. Вход проверяется через $defs.ProtocolInput.

№1 возвращает speech-объект с segments, durationSeconds, detectedSpeakers.
Интеграционный слой №3 передаёт segments как transcript в модуль №2.
Реплики должны содержать id, speakerId, start, end, text; speakerName и language необязательны.
Время start/end — секунды от начала записи. speakerId обозначает голос, не установленное имя человека.
Говорящий и исполнитель поручения могут быть разными людьми.

metadata содержит необязательные title, meetingDate (YYYY-MM-DD), timeZone (название IANA).
Неизвестные дата и часовой пояс могут быть null. Нельзя подставлять текущую дату вместо даты совещания.
Добавление metadata нужно согласовать с №3; формат TranscriptSegment при этом не меняется.

Выход: title, исходный transcript, summary, topics и actionItems.
Каждое поручение: id, task, assignee, deadlineText, deadline, sourceSegmentIds, confidence, needsReview;
assignedBy — необязательное имя автора поручения, если оно подтверждено.
Пустой actionItems допустим: обсуждение может не содержать поручений.

## Правила проверки сверх JSON Schema

- id реплик и id поручений уникальны в своих списках.
- end >= start; исходный текст, порядок и времена реплик сохраняются.
- Каждый sourceSegmentIds ссылается на существующую реплику и действительно подтверждает поручение.
- Нет ответственного: assignee=null, needsReview=true.
- Нет срока: deadlineText=null, deadline=null, needsReview=true.
- Есть относительный срок, но недостаточно контекста: сохранить deadlineText, deadline=null, needsReview=true.
- Неоднозначные сроки не нормализовать догадкой; правило вычисления даты должно быть документировано.
- Идея или предположение сами по себе не являются поручением.
- confidence в диапазоне 0..1 — оценка модели, не калиброванная вероятность.
- Второй AI-проход проверяет источники, но не гарантирует отсутствие ошибок.
- Валидатор должен включать проверку format=date; не все библиотеки включают её автоматически.
- Связи между полями и ссылки проверяются кодом на следующем этапе.

## Установка и запуск модуля

Python 3.11+; проверено на Python 3.14.6 / Windows. Внешняя Python-зависимость — jsonschema 4.26.0.
Команды PowerShell из корня репозитория:

```powershell
python -m venv protocol/.venv
protocol/.venv/Scripts/python -m pip install -r protocol/requirements.txt
protocol/.venv/Scripts/python -m protocol protocol/fixtures/input.demo.json --validate-only
protocol/.venv/Scripts/python -m unittest discover -s protocol/tests -v
```

Для реального AI нужен отдельно установленный Ollama и скачанная локальная multilingual модель.
Проверенная конфигурация: Ollama 0.34.3, qwen3:4b (359d7dd4bcda), RTX 4060 Laptop 8 ГБ VRAM,
около 16 ГБ RAM. Ollama ps показал 100% GPU, размер в памяти около 5.1 ГБ, контекст 16384.
Загрузка модели около 2.5 ГБ; установщик Ollama отдельно около 1.46 ГБ.
Необходим работающий Ollama на loopback. Реализация /api/chat сверена с https://docs.ollama.com/api/chat.

Для выделенного локального сервера используйте `powershell -File protocol/start-local.ps1` в отдельном терминале.
Скрипт запускает Ollama на 127.0.0.1:11435 с OLLAMA_NO_CLOUD=1, без изменения постоянных переменных Windows.
Для клиента в этом случае задайте LOCAL_LLM_BASE_URL=http://127.0.0.1:11435.
В другом PowerShell задайте `$env:OLLAMA_HOST='127.0.0.1:11435'` и выполните `ollama pull qwen3:4b`.
Если текущий терминал ещё не видит ollama после установки, используйте полный путь
`& "$env:LOCALAPPDATA\Programs\Ollama\ollama.exe" pull qwen3:4b`.

```powershell
$env:LOCAL_LLM_BASE_URL = 'http://127.0.0.1:11435'
$env:LOCAL_LLM_MODEL = 'qwen3:4b'
$env:LOCAL_LLM_TIMEOUT = '600'
protocol/.venv/Scripts/python -m protocol protocol/fixtures/input.demo.json
```

Отдельная проверка реального AI на синтетическом примере:

```powershell
protocol/.venv/Scripts/python -m protocol.smoke
```

Она проверяет извлечение пяти поручений и основные поля, исключение идеи и наличие summary;
exit code 0 — эти проверки пройдены. Это маленький smoke test, а не оценка точности на реальных совещаниях.

LOCAL_LLM_MODEL обязателен, URL по умолчанию — http://127.0.0.1:11434,
тайм-аут по умолчанию — 600 секунд на запрос. CLI не загружает .env автоматически.
Пример переменных находится в protocol/.env.example. Ключи облачных API не нужны.
CLI пишет JSON в stdout, этапы и ошибки — в stderr; exit code 1 при ошибке.
Для Linux/macOS заменить protocol/.venv/Scripts/python на protocol/.venv/bin/python.

## Границы и ограничения

- Адаптер разрешает только loopback URL, отключает proxy и HTTP redirects.
  Настройки самого Ollama также должны обеспечивать локальную обработку: не использовать cloud-модели.
- В локальную модель передавался только синтетический fixture; реальные записи и облачные API не использовались.
- Лимиты: 120000 символов текста, 5000 реплик, end до 1800 секунд (30 минут).
  Реальную длительность аудиофайла должен проверять speech/backend.
- Вход делится по репликам на части до 6000 символов сериализованного JSON с перекрытием до двух реплик.
  Одна слишком длинная реплика отклоняется: speech должен разделить её. Скрытой обрезки нет.
- На каждую часть: extractor, verifier кандидатов, summary. До 100 кандидатов на часть.
  Полный исходный транскрипт сохраняется. Точные повторы поручений из перекрытий удаляются.
  Различающиеся формулировки одной задачи могут остаться; поздние отмены и контекст за пределами
  перекрытия не сверяются глобально. Это ограничение текущей обработки длинных совещаний.
- Саммари объединяет цитаты всех частей без повторных строк; оно может содержать больше пяти реплик.
- on_progress дополнительно выдаёт chunk:N/M; done означает завершение всего протокола.
- Тайм-аут 600 секунд относится к одному запросу модели, не ко всему совещанию.
- Для UI подготовлена отдельная ветка codex/long-meeting-ui от codex/app-demo:
  ожидание 3600 секунд, файл до 400 МиБ. При интеграции повторить ограничения на сервере
  и настроить HTTP/proxy timeouts; для устойчивой обработки нужны фоновые задания с polling.
  Увеличение браузерного тайм-аута само по себе не настраивает сервер и не подключает speech.
- `python -m protocol.smoke --long`: реальный Qwen3 4B обработал синтетический транскрипт
  44776 символов / 67 реплик с временной шкалой до 1800 секунд в 12 частях за 117.73 секунды.
  Все пять поручений в конце найдены, исходный текст сохранён. Это не тест реального аудио
  и не гарантия времени обработки любых 30-минутных записей.
- Неоднозначные «до пятницы», «на этой неделе», «15 октября» без года оставляются без даты.
  Поддержаны даты с годом (ISO, DD.MM.YYYY, DD/MM/YYYY, русское название месяца),
  «сегодня/бүгін», «завтра/ертең», «через N дней/недель» при известной дате совещания.
  Не поддержанные формулировки сохраняются в deadlineText и требуют проверки человеком.
- Срок должен быть точной цитатой из указанных реплик; нормализованная дата модели игнорируется.
- Verifier удаляет неподтверждённые поручения, очищает неподтверждённые имя/срок/автора.
  Он снижает риск ошибок, но не гарантирует достоверность.
- Summary — извлекающее резюме: модель выбирает до пяти важных реплик и группирует темы;
  код вставляет исходные реплики дословно. Это исключает искажения перевода в тексте саммари,
  но выбор реплик и названия тем всё ещё могут быть неточны. Свободный пересказ не используется.
- needsReview снижает confidence до максимум 0.5; это продуктовая эвристика, не вероятность.
- Нет UI, экспорта DOCX, speech или HTTP-сервера: это зона участника №3 / №1.
  Для другого backend №3 может вызвать CLI как subprocess или импортировать Python-функцию.
- Fixtures синтетические. Тестовый ScriptedLLM существует только в тестах и не является demo AI.
- Реальный smoke test на RU/KK/mixed после исправления инструкций прошёл за 12.56 секунды
  на прогретой модели: пять поручений, два абсолютных срока, сохранён «осы аптада»,
  отсутствующие значения null, идея не стала поручением. Это один небольшой пример,
  не измерение точности на корпусе и не гарантия скорости для длинной записи.
- Первые прогоны выявили неверную классификацию verifier и искажение казахского пересказа;
  исправлены инструкции, summary переведён на выбор исходных цитат. Smoke test дополнен
  проверками сохранения казахского срока и текста поручения.
- Осталось подключить общий сценарий с командой и проверить реальные размеченные транскрипты.
