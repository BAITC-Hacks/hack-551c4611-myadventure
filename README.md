# JINALYS AI

Локальный AI-секретарь совещаний. Этот репозиторий сейчас содержит **UI-прототип участника №3**, демо-данные, DOCX-экспорт и контракт для интеграции. Полный AI pipeline в этой ветке пока не подключён. По сообщению команды, модули участников №1/№2 готовы отдельно; их код и сквозной сценарий здесь ещё не проверены.

## Команде: как объединить части

Основной интегратор — участник №2. Пошаговый гайд: [docs/TEAM_HANDOFF.md](docs/TEAM_HANDOFF.md). Краткий API-контракт: [docs/integration.md](docs/integration.md), точные схемы: [lib/contracts.ts](lib/contracts.ts). Ветка интерфейса: `codex/app-demo`.

## Реализовано
- Казахский веб-интерфейс, адаптивная верстка.
- Выбор/перетаскивание MP3/WAV, проверка пустого файла и лимита 400 МБ.
- Явно обозначенный демо-сценарий с русским, казахским и смешанным текстом.
- Саммари, темы, поручения, ответственные, сроки, confidence, needsReview.
- Переход от поручения к исходным репликам с подсветкой.
- Имена спикеров редактируются в транскрипте; назначенные ответственные автоматически не изменяются.
- DOCX с датой, саммари, темами, поручениями и транскриптом. Демо помечается и в документе.
- Валидация ответа API через Zod, ошибки, отмена и таймаут 3600 секунд (60 минут).

## Ещё не реализовано
Распознавание аудио, диаризация, локальная LLM, extractor/verifier/summary agents, реальный прогресс AI, PDF, хранение результатов, запись с микрофона, Teams/Zoom/Meet, напоминания. Демо-текст не доказывает качество распознавания RU/KZ. Для обязательного минимума кейса нужны модули участников №1 и №2 и реальные аудиотесты.

## Архитектура
```text
MP3/WAV → Web UI → POST /api/meetings
                         ↓ подключить
                 Local STT / diarization (№1)
                         ↓ TranscriptSegment[]
                 Local protocol AI (№2)
                         ↓ MeetingProtocol
                 Zod → UI → DOCX (№3)

Кнопка «Демоны ашу» → lib/demo.ts → UI → DOCX
```
`app/api/meetings/route.ts` намеренно отвечает 503 PIPELINE_NOT_CONFIGURED. Он не подменяет обработку аудио фикстурой. Файлы пока не сохраняются и не обрабатываются. Клиентские ограничения файла необходимо повторить в backend при интеграции, включая проверку реального формата и длительности.

## Стек и требования
Next.js App Router, React, TypeScript strict, CSS, lucide-react, Zod, docx. Точные версии закреплены package-lock.json. Node.js 22.18+ (для встроенного выполнения TypeScript-тестов), npm. Проверено на Windows с Node 26.8.1/npm 11.19.0. UI не требует GPU, Python, FFmpeg, Docker или AI-моделей. Требования AI-модулей будут добавлены после интеграции; производительность и расход памяти не измерены.

## Установка и запуск
Для отдельного просмотра UI в новой папке (не поверх рабочего backend):
```powershell
git clone --branch codex/app-demo https://github.com/BAITC-Hacks/hack-551c4611-myadventure.git jinalys-ui
cd jinalys-ui
```

В PowerShell из корня этого репозитория:
```powershell
npm.cmd ci
npm.cmd run dev
```
Открыть http://127.0.0.1:3000. На Linux/macOS использовать `npm` вместо `npm.cmd`. Для установки пакетов нужен интернет; UI и демо не требуют облачных AI API.

Production:
```powershell
npm.cmd run build
npm.cmd start
```
Не запускать dev и start одновременно на одном порту.

## Проверка основного демо
1. Запустить приложение и открыть адрес выше.
2. Нажать «Демоны ашу».
3. Проверить отметку демо, 3 участников и 3 поручения.
4. Открыть «Тапсырмалар»: у тестирования нет ответственного и срока, стоит «Тексеру қажет».
5. Нажать «Дереккөзді көру»: открывается транскрипт с нужными репликами.
6. В «Толық мәтін» при необходимости изменить имя спикера.
7. Нажать «DOCX жүктеу», открыть jinalys-demo.docx в Word/LibreOffice.
8. Нажать «Жаңа жиналыс». Выбрать непустой MP3/WAV, нажать «Хаттама жасау»: до интеграции ожидается честное сообщение об отсутствии AI-модуля.

Демо-данные: `lib/demo.ts`. Записи аудио в репозитории пока нет. Для проверки настоящего AI команда должна добавить смоделированные RU/KZ/mixed записи и проверить извлечённые поручения. Реальные записи для показа необходимо обезличить.

## Переменные окружения и модели
UI сейчас не использует переменные окружения, копировать .env.example необязательно. Демо включается отдельной кнопкой. Local runtime, модель, пути, команды скачивания и настройки фиксируют участники №1/№2 при интеграции; здесь они намеренно не выдуманы.

## Приватность
Нет внешних AI вызовов, CDN-шрифтов и аналитики в коде приложения. dev/start слушают 127.0.0.1. Демо и DOCX обрабатываются локально в браузере. Реальный режим должен вызывать только local/self-hosted модели: отправка аудио/текста внешним cloud AI запрещена ТЗ. Закрытый промышленный контур, аутентификация, политика хранения и другие production меры пока не реализованы. Перед записью живая система должна уведомлять участников; в MVP записи с микрофона нет.

## Проверки
```powershell
npm.cmd test
npm.cmd run typecheck
npm.cmd run build
```
Отдельный lint пока не настроен. Проверки покрывают контракт демо, ссылки на реплики, неизвестные сроки/ответственных, неверные файлы/ответы и генерацию DOCX. Браузерные проверки выполняются вручную.

## Развитие
После подключения и проверки реального pipeline: PDF, обработка видео, live-запись, напоминания, интеграции СЭД и платформ совещаний. Эти функции не входят в готовый UI-прототип.

## Көрініс және іздеу / Appearance and search
- «Жарық» — ақ/жасыл; «Қараңғы» — қара/қанық көк.
- «Жұмыс» — жинақы көрініс; «Тыныш» — жұмсақ шалфей/құм реңктері (жарық), жұмсақ күлгін (қараңғы), кеңірек мәтін аралығы.
- Тақырып пен көңіл-күй тәуелсіз, 4 комбинация бар. Таңдау браузердің localStorage ішінде jinalys-appearance кілтімен сақталады; жиналыс деректері онда сақталмайды. Браузер сақтауды бұғаттаса, көрініс осы ашық бетте жұмыс істейді.
- Тапсырмалардан мәтін, жауапты және мерзім бойынша іздеу; «Тек тексеру қажет» сүзгісі.
- Транскрипттен мәтін/сөйлеуші бойынша іздеу. Дереккөзге өту іздеу өрісін тазартып, бастапқы репликаны көрсетеді.
- Іздеу мен сүзгі DOCX мазмұнын өзгертпейді: толық хаттама экспортталады.
